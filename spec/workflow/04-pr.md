# Stage 4: PR

**Purpose:** a small, reviewable pull request that links code to spec.
**Who:** dev agent. **Inputs:** verified change folder.

## Steps
1. Confirm `verification.md` status is PASS.
2. Rebase on latest `main`; resolve conflicts; re-run tests if anything changed.
3. Title: `KAN-<n>: <summary>`. Body from `.github/pull_request_template.md`, filled with real content: link to the change folder, acceptance criteria with evidence, spec deltas summary, docs and contracts updated.
4. Size check: under about 400 changed lines excluding generated files; otherwise explain or split.
5. Push the branch and open the PR. Wait for CI (lint, tests, `spec_check`, secret scan, import rules).
6. Move the Jira story to In Review and comment with the PR link.

## Exit criteria (gate 4)
PR open, CI green, template complete.

## Failure handling
CI red: fix and push; do not request review until green. Never force-push over reviewed commits without telling the reviewer.
