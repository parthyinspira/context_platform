---
name: demo-data
description: Generate deterministic, non-sensitive demo and test data: sample repos (SQL/dbt, Java, .NET, Talend-like), a sample Postgres database, and policy/FAQ documents with a known lineage chain and a deliberately broken job.
---

Used by harvester tests (KAN-88) and the demo agents (KAN-98). Output goes under `fixtures/` (follow the repo layout); everything is generated by a script so it is reproducible.

Include:
1. **SQL/dbt repo:** tables, views and a model chain `source table -> staging -> mart table`.
2. **Talend-like repo:** a few small `.item`/`.properties` job files plus large dummy binaries and screenshots, so the plan must skip them (proves scoping).
3. **Java and .NET repos:** small projects with build files, SQL resources and a `bin/`/`target/` folder to be ignored.
4. **Shell scripts** that read and write the sample tables.
5. **Sample Postgres database:** schemas, tables, views, a stored procedure, comments and row counts, loaded by compose.
6. **Documents:** policy and FAQ docs (md, docx, pdf) and an Excel file; mark some `internal` and one `restricted` for sensitivity tests.
7. **Seeded scenarios:** a lineage chain ending in a dashboard definition; one upstream job that is "broken" (stale or failing) for the prod-support agent; a repo with a file containing a fake secret to test redaction (clearly fake values).
8. Document expected entities and edges in `fixtures/EXPECTED.md` so tests and evals can assert on them.

All data is synthetic. No real company data, names or credentials. Run `secret-scan` afterwards.
